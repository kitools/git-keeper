首先我想提出，scan 的时候，不是 git 仓库且不在 git 仓库下的目录得列出来；
但是转念一想，那得挖多少层呢？你想过吗？
是不是得有一个「挖掘深度」的参数，默认是 3 之类。还有比如「同一目录最多挖多少个子目录都不是 git 仓库时就不再挖这个目录」，默认比如是 500 之类。因为 500 个子目录都不是 git 仓库，那这个目录就很诡异，不符合人类习惯，很可能是机器管理的非 git 仓库类的目录，多半就不会再有 git 仓库了；即使有，这个目录也足够奇怪，值得单独列出来。当然，这些情况触发的时候都得报告。

1、不要叫 --depth ，语义要更清晰，叫 --willing-depth ，表示从任何非 repo 开始「寻找下一个 repo」所愿意探测的深度。默认 3。
2、同样，宽度叫 --willing-breadth，表示「寻找下一个 repo」所愿意探测的宽度。假如在此范围内找到了一个 repo，那就重新计数。默认 500。

不仅如此，还有，不是 repo 的目录也要报告。且只报告连续非 repo 的最上级目录。
